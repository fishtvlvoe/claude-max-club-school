# 討論中一題一題等確認，不要擅自跳下一步

## 問題

在創作或設計的討論流程中，Claude 在用戶還沒對上一個決策點確認時，就自動進入下一步。

常見案例：
- 提出三個標題候選，用戶還在思考，Claude 就開始為「最好的那個」繼續延伸
- 用戶說「嗯，第二個不錯」（尚未明確選定），Claude 就以第二個為基礎繼續產出內容
- 討論架構時，設計圖還沒確認，Claude 就開始寫實作代碼

結果是用戶必須把 Claude 拉回上一步重來，增加對話往返成本。

## 原因

Claude 把「看起來用戶傾向某個選項」等同於「用戶已確認」，跳過了等待明確確認的步驟。

## 解決方案

任何討論/創作流程中，每個決策點提出後：
- **等用戶明確說「好」「可以」「就這個」才進下一步**
- 用戶沒有明確確認 → 閉嘴等，不要繼續產出

「看起來傾向 A」不等於「選了 A」。

## 可複用的 CLAUDE.md 規則

把這段貼進你的 CLAUDE.md：

```markdown
- 討論中每個決策點提出後，MUST 等用戶明確確認（「好」「可以」「就這個」）才進下一步。
- 用戶還在思考、沒有明確回應時 → 閉嘴等，不要繼續產出或進下一 Phase。
- 「用戶傾向 A」≠「用戶選了 A」。
```
