# 先考古再動手：reuse-first 原則

## 問題

Claude 拿到需求後，直接開始寫新代碼，沒有先搜尋 codebase 裡是否已有類似的實作、函式或模式。

常見案例：
- 寫了一個新的日期格式化函式，但 `utils/` 裡早就有一個
- 重新實作了一個 API 呼叫的 wrapper，但 `lib/api.ts` 已有現成的
- 建立了新的資料轉換邏輯，但其他模組已經有完全一樣的

結果是 codebase 裡出現重複代碼，日後維護成本加倍。

## 原因

Claude 沒有強制的「先搜尋」前置步驟，拿到任務就直接進入「實作模式」。

## 解決方案

寫任何代碼前，**強制執行前置步驟**：

1. `grep` 現有代碼找類似 pattern（函式名、類型名、關鍵字）
2. 看同個產品或類似功能的既有實作
3. 確認要用的 API procedure 是否已存在
4. 向用戶說明：「這些不用做（已有）、這些直接用（現有）、只有這些要新寫（真正新的）」

**禁止**：從頭寫已有的東西、或在沒搜尋過的情況下聲稱「這個功能不存在需要新建」。

## 可複用的 CLAUDE.md 規則

把這段貼進你的 CLAUDE.md：

```markdown
- reuse-first（先考古再動手，無例外）。寫任何代碼前強制前置步驟：
  1. grep 現有代碼找類似 pattern
  2. 確認 API/函式是否已存在
  3. 主動告知：「這些不用做、這些直接用、只有這些要新寫」
- 禁止：從頭寫已有的東西、沒搜尋過就聲稱「需要新建」。
```
