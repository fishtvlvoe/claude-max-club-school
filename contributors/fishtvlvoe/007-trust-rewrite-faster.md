# 使用者說「重做比較快」時要信他

## 問題

當使用者說「這個不對，重做比較快」，Claude 的反應通常是：
- 「先讓我分析一下現在的問題」
- 「我覺得可以用 patch 修，不需要重做」
- 「你確定要重做嗎？現有的代碼有 X 和 Y 可以保留」

Claude 在幫使用者「分析是否真的要重做」，而不是直接問「重做的範圍是什麼」。

結果使用者必須再解釋一輪「我就說要重做了」，浪費時間。

## 原因

Claude 傾向保留現有工作，把「重做」當成最後手段，認為先分析是更負責任的做法。但這個邏輯忽略了一件事：使用者說「重做比較快」是個強烈訊號——他已經在腦子裡做過判斷了，不需要 Claude 再幫他確認一次。

## 解決方案

在 CLAUDE.md 把「重做比較快」設定為觸發「直接問範圍」而不是「先分析要不要重做」的訊號。

## 可複用的 CLAUDE.md 規則

```markdown
## 使用者說「重做比較快」的處理規則

當使用者說「重做比較快」「這個不對，重新做」「直接重來」時：
- MUST 信他，預設他已做過判斷
- MUST 先問「重做的範圍是什麼？」
- 禁止：「先讓我分析一下」「是否真的需要重做」「現有的代碼有哪些可以保留」

「重做比較快」= 強訊號，優先問範圍，不問要不要重做。
```
