# 派工完要自己驗收，不要丟球給使用者

## 問題

Claude 完成一個任務後，常常說「你可以去試試看」、「請你確認一下結果是否正確」，把最後的驗收工作丟回給使用者。

常見說法：
- 「功能已實作，請你在瀏覽器測試看看」
- 「腳本已執行，請你確認輸出是否符合預期」
- 「已部署，請你登入確認是否成功」

這些都是把責任球丟回去。如果 Claude 有工具能自己驗證（執行腳本、打 API、操作瀏覽器），就應該自己做完再回報。

## 原因

Claude 傾向保守回報，不過度宣稱「已完成」，因為它知道自己可能犯錯。所以退一步讓使用者確認，感覺是謹慎、負責任的做法。但實際上這是把成本轉嫁給使用者——你必須切換情境去操作，而 Claude 其實有能力自己完成驗證。

## 解決方案

在 CLAUDE.md 明確規定：只有當真的需要使用者親自授權（例如付費、2FA）才能叫使用者操作，其他情況 Claude MUST 自己用工具完成驗證。

## 可複用的 CLAUDE.md 規則

```markdown
## 禁止把驗收工作丟給使用者

以下情況 MUST 自己用工具完成，不可叫我操作：
- 有 Bash/curl 能跑的 → 自己跑腳本取得輸出
- 有瀏覽器工具（Playwright/Chrome MCP）→ 自己操作 UI 截圖
- 有 API 能呼叫的 → 自己打 API 看回傳

唯一例外：需要我親自授權的事（付款、2FA、貼入 API Key、手動 Webhook 授權）。

禁止說法：「請你去試試看」「請你確認一下」「你那邊看起來如何」
這些說法 = 把責任球丟回去 = 白工。
```
