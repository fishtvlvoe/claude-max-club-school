# 討論中一題一題等確認，不要用戶還在想就跳下一步

## 問題

在多步驟的討論或決策流程中，Claude 提出了選項 A，用戶還沒有明確表示選 A，Claude 就自動往下走：

- 「好，那我就用方案 A，接下來是⋯⋯」（用戶根本沒說要 A）
- 用戶還在思考要選哪個標題，Claude 已經開始產出內文了
- 用戶說「嗯，有道理」（表示正在消化），Claude 解讀成「同意」然後繼續

這強迫用戶必須中斷思考去喊停，否則就只能跟著 Claude 的節奏走。本來想要「逐步確認」的討論，變成了「不停追趕 Claude 的輸出」。

## 原因

Claude 傾向「保持對話流暢、推進任務」，容易把「用戶沒說不」解讀為「用戶同意」。但在決策型對話中，沉默或思考性回應不等於確認——用戶可能還在比較選項，或者根本還沒看完 Claude 提出的東西。

## 解決方案

在任何需要用戶做決定的討論中：

1. **提出選項後閉嘴等**：把球交給用戶，等待明確的確認詞（「好」「可以」「就這個」「用 A」）
2. **不確定就明確問**：「你選哪個？」而不是自己猜測繼續
3. **「嗯」「有道理」「讓我想想」= 還沒確認**，繼續等，不要解讀成同意
4. **每個決策點都是一個停頓點**：不能因為前一步走得快，就跳過某個確認

特別需要這種節奏的場景：
- 方案/架構選擇討論
- 創作流程中的每個決策點（標題→結構→金句→收尾）
- 多階段任務的里程碑確認

## 可複用的 CLAUDE.md 規則

把這段貼進你的 CLAUDE.md：

```markdown
- 討論中每個決策點（方案選擇、步驟選項），提出後 MUST 等我明確說「好」「可以」「就這個」才繼續下一步。我說「嗯」「有道理」「讓我想想」= 還沒確認，繼續等。禁止自動把沉默或思考性回應解讀為同意。
```
