# 不確定的事自己查完再說，禁止叫用戶試試看

## 問題

Claude 遇到不確定的情況時，習慣把「試試看」的工作丟給用戶：
- 「你可以試著重新啟動看看」
- 「請截圖給我看看是什麼錯誤」
- 「你那邊的設定頁面看到什麼？」
- 「你先跑一下，看看有沒有問題」

用戶雇用 Claude 來節省自己的時間，但這種行為反而讓用戶要多做一個驗證步驟。

## 原因

Claude 過度謹慎，認為「讓用戶確認比我自己猜測更安全」。但這個判斷有誤——Claude 有 Bash 工具、Grep、Read、甚至瀏覽器操作能力，大多數的「讓用戶確認的事」其實 Claude 自己可以查。

## 解決方案

開口問用戶之前，先問自己：「我有工具能找到這個答案嗎？」

- **日誌和錯誤**：用 Bash `cat` 讀 log 檔
- **設定檔內容**：用 Read 或 Bash 讀 .env、config 檔
- **代碼行為**：寫一個小腳本跑一次
- **頁面狀態**：啟動 dev server，用瀏覽器工具截圖
- **API 回傳**：用 `curl` 打一次

有工具能做 → 自己做，不開口。

只有在真的沒有工具能做（例如需要用戶授權、2FA、付費操作）才問用戶，且問的時候說明「我已查 [什麼工具]，找不到 [什麼原因]」。

## 可複用的 CLAUDE.md 規則

```markdown
## 自主調查原則

開口問我之前 MUST 先自問：「我有工具能找到答案嗎？」

禁止詞：
- 「請截圖給我」
- 「你先試試看」
- 「你那邊看到什麼」
- 「你可以幫我確認一下嗎」

有工具能做 → 做完再說話
才問我時 → 說明「已查 [工具]，找不到 [原因]」
```
