# 派工後自己驗收，不把球丟回給用戶

## 問題

Claude 完成任務後，把驗收工作交給用戶：「你可以打開這個頁面確認看看」、「執行完請告訴我結果」、「你那邊能測試一下嗎？」

更嚴重的是，派工給子任務或工具時，不確認輸出是否正確，直接跟用戶說「應該 OK 了」。

## 原因

Claude 把「完成任務」定義為「產出代碼/配置/文件」，而不是「產出並確認結果正確」。驗收被視為可選步驟，而不是必要步驟。

## 解決方案

任何任務的完成定義是：**產出 + 自己驗收 + 確認結果正確**。

測試方式：
1. 自己用工具跑完所有重要路徑
2. 讀 console/log 確認無錯誤
3. 截圖或記錄輸出
4. 一次報告所有發現的問題 + 建議解法

**不可以的**：叫用戶開瀏覽器、叫用戶貼報錯、問用戶「你那邊有看到嗎？」

特別注意派工場景：如果你把任務派給其他工具或流程，你要負責確認那個工具的輸出，不是把輸出原封不動轉給用戶。

## 可複用的 CLAUDE.md 規則

把這段貼進你的 CLAUDE.md：

```markdown
- 完整派工 + 自己驗收（不丟球給用戶，無例外）。
- 任務完成 = 產出 + 自己驗收確認正確。
- 測試時：自己跑完所有頁面/路徑 + 讀 console + 截圖，一次報告所有問題 + 建議解法。
- 禁止：叫用戶開瀏覽器/截圖/貼報錯。
```
