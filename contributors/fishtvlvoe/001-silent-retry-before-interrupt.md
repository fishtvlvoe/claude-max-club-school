# 工具失敗時靜默試備案，別打斷用戶

## 問題

Claude 在執行工具或指令時，一旦第一個方案失敗，就立刻向用戶回報「這個方法不行」，要求用戶指示下一步。

例如：呼叫一個 API 拿到錯誤回應，Claude 馬上說「API 回傳 403，請問要怎麼處理？」——但其實還有其他方案可以先試。

## 原因

Claude 預設行為是「透明」和「不擅自決定」，在不確定時傾向請示用戶。但這造成用戶在工作流程中被頻繁打斷，需要處理本來可以自動解決的細節。

## 解決方案

遇阻時先靜默嘗試備案 B、C、D，**全部失敗才向用戶回報**，且回報時要說清楚：
1. 嘗試了哪些方案
2. 每個方案的實際錯誤
3. 目前狀態

「試 B/C/D → 全部失敗 → 回報」這個流程讓用戶只需要處理真正無法自動解決的問題。

## 可複用的 CLAUDE.md 規則

把這段貼進你的 CLAUDE.md：

```markdown
- 遇到工具失敗或阻礙，先靜默嘗試所有備案（B/C/D 方案），全部失敗才回報用戶。
- 回報時說明：嘗試了哪些方案、各自的錯誤、目前狀態。
- 禁止在第一個方案失敗後就中途打斷用戶要求指示。
```
